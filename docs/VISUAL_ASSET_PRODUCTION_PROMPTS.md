# Surveillance Survivor — Graphics Asset Generation Prompts

**194 shipped sprites, 20 weapon VFX assets and 8 unproduced animation clips.** Every entry is a ready-to-paste prompt carrying the pixel size the art is actually authored at.

The highest-value entries are the ones that **do not exist yet**: 17 weapon VFX assets and 8 animation clips are specified in the repo but unproduced, so generating them adds something the game currently lacks rather than replacing art already shipping.

> Generated by `scripts/generate_visual_asset_prompts.py`. Do not hand-edit — rerun the script. Names, sizes, city themes and guard statistics are read from the repository, so adding a role or resizing an entry is picked up automatically.

---

## Read this before generating anything

**Generate at the source size quoted in each prompt, not the display size.** These differ, often by a lot. The player renders at 54x72 on screen but the art is authored 414x596; guards render 40x52 from 256x320. SpriteKit downscales. Generating at display size would produce art at roughly a seventh of the resolution the existing set uses, and it would look soft next to everything already shipped.

**Save each file under the exact asset name given, as `.png`, into `Resources/RuntimeSprites/`.** The runtime resolves textures by name. A mismatch silently falls back to a coloured shape node and the game keeps running, which is precisely why a wrong name is easy to miss.

| Requirement | Why it matters |
| --- | --- |
| Exact source dimensions as listed | Matches the resolution of the shipped set; wrong sizes look soft or over-sharp after scaling |
| Real alpha transparency on everything except the tiling ground textures | Sprites composite over a busy playfield |
| sRGB colour space | `make assets-check` rejects other profiles |
| No text, watermark, signature or UI chrome | The HUD is native SwiftUI; baked text cannot localise or scale |
| Player frames share one canvas and one base line | Frame-to-frame drift reads as the character jittering |
| The 3 LPR states share one canvas and one base line | The pole must not appear to move when it takes damage |

Two colour rules carry gameplay meaning rather than taste:

- **Cyan is reserved for player-facing signals** — the player's visor, the Blind Spot extraction marker, the targeting reticle. Nothing hostile may use it.
- **Landmark rings are dim amber; the Blind Spot is cyan.** Deliberately separated so the exit is never mistaken for scenery.
